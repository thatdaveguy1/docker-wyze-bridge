# Contributing to Docker Wyze Bridge

## Quick Start

```bash
# Clone
git clone <repo-url>
cd docker-wyze-bridge

# Create venv (Python 3.13+ required)
python3.13 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pip install -r app/requirements.txt

# Run tests
python -m pytest tests/ --timeout=60 -q    # 349 Python tests
go test ./whep_proxy/... -v -count=1        # 30 Go tests

# Build check (verifies HA mirrors are in sync)
./scripts/build.sh --check
```

## Project Structure

```
app/                    Canonical Python source (the bridge)
whep_proxy/             Canonical Go source (WHEP proxy)
tests/                  Python test suite
scripts/                Build, deploy, and verification scripts
docker/                 Dockerfiles
home_assistant/         Generated HA add-on tree (do not edit directly)
.ha_live_addon/         Generated dev HA add-on tree (do not edit directly)
runtime_overlays/       Target-specific overrides (.env, build.env)
docs/                   Architecture documentation
```

**Key rule**: `app/` and `whep_proxy/` are canonical. `home_assistant/` and
`.ha_live_addon/` are generated by `./scripts/build.sh`. Never edit generated
trees directly. After changing `app/` or `whep_proxy/`, run:

```bash
./scripts/build.sh --apply home_assistant
./scripts/build.sh --apply ha_live_addon
./scripts/build.sh --check
```

## Testing

### Python Tests
Tests live in `tests/` and use `unittest` with `pytest` as the runner.

```bash
# Full suite
python -m pytest tests/ --timeout=60 -q

# Single test
python -m pytest tests/test_kvs_stream_get_info.py -v

# With verbose output
python -m pytest tests/ -v --tb=long
```

**Important**: Several test files install fake modules in `sys.modules` to
avoid loading native TUTK C libraries. If you add a new test file that needs
fake modules, use `patch.dict(sys.modules, ...)` in `setUpClass`/`tearDownClass`
rather than module-level `setdefault`, to avoid polluting other test modules.

### Go Tests
```bash
go test ./whep_proxy/... -v -count=1
```

### Build Check
```bash
./scripts/build.sh --check
```

## Code Style

- **Python**: Follow existing style. Line length 120. Type hints encouraged
  (81% coverage currently). `ruff` and `mypy` configs are in `pyproject.toml`.
- **Go**: Follow `gofmt` conventions. All files in `whep_proxy/` stay in
  `package main` so tests can access fields directly.
- **No debug `print()` in production code**: Use `logging.getLogger(__name__)`.
- **Broad `except Exception`**: Add a comment explaining why. Only narrow when
  confident about what exceptions can be raised.

## Commit Conventions

- Write concise commit messages focusing on "why" not "what"
- Check for sensitive info (API keys, passwords, IPs) before committing
- Stage and commit with:

```bash
git commit -m "$(cat <<'EOF'
Your commit message here.

Generated with [Devin](https://devin.ai)

Co-Authored-By: Devin <158243242+devin-ai-integration[bot]@users.noreply.github.com>
EOF
)"
```

## Before Opening a PR

1. All 349 Python tests pass
2. All 30 Go tests pass
3. `./scripts/build.sh --check` passes
4. No new debug `print()` statements in production code
5. New modules have docstrings explaining their purpose
